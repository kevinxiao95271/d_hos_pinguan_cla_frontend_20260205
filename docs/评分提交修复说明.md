## 🔍 问题原因

### 前端使用了错误的字段名

前端代码中的字段名与后端API要求的字段名**完全不匹配**！

| 前端字段名 | 后端字段名 | 说明 |
|-----------|-----------|------|
| ❌ `taskId` | ✅ `reviewTaskId` | 任务ID |
| ❌ `planScore` | ✅ `plan` | 计划得分 |
| ❌ `problemAnalysisScore` | ✅ `problem` | 问题得分 |
| ❌ `implementationScore` | ✅ `action` | 措施得分 |
| ❌ `resultScore` | ✅ `success` | 成效得分 |
| ❌ `reviewScore` | ✅ `review` | 回顾得分 |
| ❌ `operationScore` | ✅ `operation` | 操作得分 |
| ❌ `presentationScore` | ✅ `presentation` | 展示得分 |
| ❌ `highlights` | ✅ `highlight` | 亮点（注意单数！）|
| ❌ `shortcomings` | ✅ `weakness` | 不足 |

## 📊 后端API要求

### 请求格式

```
POST /api/reviews/scores
Authorization: Bearer {token}
Content-Type: application/json
```

### 请求体

```json
{
  "reviewTaskId": 115,           // ⭐ 任务ID（必填）
  "plan": 18,                    // 计划得分 (0-100)
  "problem": 17,                 // 问题得分 (0-100)
  "action": 19,                  // 措施得分 (0-100)
  "success": 18,                 // 成效得分 (0-100)
  "review": 16,                  // 回顾得分 (0-100)
  "operation": 0,                // 操作得分 (0-100)
  "presentation": 0,             // 展示得分 (0-100)
  "highlight": "项目主题明确...", // ⭐ 必填！亮点描述
  "weakness": "建议进一步..."    // ⭐ 必填！不足描述
}
```

### 响应格式

```json
{
  "success": true,
  "data": {
    "id": 49,
    "totalScore": 88,
    "status": "SCORED"
  },
  "message": null
}
```

## ⚠️ 关键点

1. **必须使用 `reviewTaskId`，不是 `taskId`**
   - `reviewTaskId` = 从任务列表的 `id` 字段获取
   - ❌ 不要使用 `registrationId`（那是项目ID）

2. **字段名没有 `Score` 后缀**
   - ✅ `plan`，不是 `planScore`
   - ✅ `problem`，不是 `problemAnalysisScore`
   - ✅ `action`，不是 `implementationScore`
   - ✅ `success`，不是 `resultScore`

3. **亮点和不足是单数形式**
   - ✅ `highlight`（单数），不是 `highlights`（复数）
   - ✅ `weakness`（单数），不是 `shortcomings`

4. **亮点和不足是必填字段**
   - 不能为空字符串
   - 必须提供有意义的内容

5. **评分范围**
   - 每项得分：0-100
   - 总分由后端自动计算
