## 根本原因

后端数据库中，**每个字典类型都维护了两套数据：**

1. **新版Code命名规范**（语义化code）：例如 `case_quality`、`cost_efficiency`、`appointment` 等
2. **旧版Code命名规范**（编号式code）：例如 `subject_type_1`、`method_1` 等

**这两套数据具有相同的label（中文显示名称），但code不同。**

---

## 前端表现

由于前端使用 `v-for="item in subjectTypes"` 遍历所有数据项，并以 `item.label` 作为下拉选项的显示文本，导致用户看到**相同的中文选项出现两次**。

**示例（主题类型下拉框）：**
```
- 病例质量      (code: case_quality)
- 成本效益      (code: cost_efficiency)
- ...
- 患者护理      (code: subject_type_1)
- 病例质量      (code: subject_type_2)  ← 重复！
- 时间效益      (code: subject_type_3)
- 成本效益      (code: subject_type_4)  ← 重复！
- ...
```

## 修复建议（给后端）

### ⚠️ 前端代码已统一"其他"选项判断

**前端已将所有"其他"选项的判断统一为 `code === 'other'`：**
- 主题类型：`subjectTypeCode === 'other'`（已移除 `subject_type_11` 判断）
- 运用手法：`methodCode === 'other'`
- 改善就医感受：`experienceImproveCode === 'other'`
- 医疗质量安全主题：`qualityTopicCode === 'other'`

**后端必须确保所有"其他"选项的code统一为 `'other'`！**

---

### 方案1：删除旧数据（推荐）

**保留新版语义化code，删除旧版编号式code：**

```sql
-- 1. 先统一"其他"选项的code
UPDATE dictionaries SET code = 'other' 
WHERE type = 'subject_type' AND (code = 'subject_type_11' OR label LIKE '%其他%');

-- 2. 删除 subject_type 的其他旧版数据
DELETE FROM dictionaries WHERE code LIKE 'subject_type_%' AND code != 'other';

-- 3. 删除 method 的旧版数据
DELETE FROM dictionaries WHERE code LIKE 'method_%';

-- 依此类推...
```

**优点：**
- 彻底解决重复问题
- 代码更易读维护（语义化命名）
- 数据库更简洁

**注意事项：**
- **必须保留所有 `code='other'` 的数据**
- 确认前端/报名数据中没有使用旧版code
- 如有使用，需要先进行数据迁移

---

### 方案2：停用旧数据

**将旧版数据的 `active` 字段设为 `false`：**

```sql
-- 示例：停用 subject_type 的旧版数据
UPDATE dictionaries SET active = false WHERE code LIKE 'subject_type_%';

-- 示例：停用 method 的旧版数据
UPDATE dictionaries SET active = false WHERE code LIKE 'method_%';
```

**后端API需同步修改，只返回 `active = true` 的数据：**

```java
// 伪代码示例
public List<Dictionary> getDictionariesByType(String type) {
    return dictionaryRepository
        .findByTypeAndActive(type, true);  // 只返回active=true的数据
}
```

**优点：**
- 保留旧数据，方便回滚
- 兼容性好

**缺点：**
- 数据库冗余
- 需要修改后端API逻辑

---

### 方案3：前端去重（临时方案，不推荐）

前端根据 `label` 去重，但这是**治标不治本**的做法，不推荐长期使用。

## 结论
