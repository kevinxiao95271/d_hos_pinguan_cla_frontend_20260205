# OPS报名列表 - 400错误修复

**修复时间：** 2026-02-28  
**问题：** API返回400错误  
**状态：** ✅ 已修复

---

## 🐛 问题描述

访问OPS报名列表页面时，出现以下错误：

```
Failed to load resource: the server responded with a status of 400 (Bad Request)
GET /api/admin/registrations/filter?page=0&size=20
```

**错误信息：**
```javascript
加载报名列表失败: AxiosError: Request failed with status code 400
```

---

## 🔍 问题分析

### 根本原因

`filterRegistrations` API **需要 `competitionId` 作为必需参数**，但OPS报名列表页面在首次加载时没有传递这个参数。

### 对比分析

**组委会页面（正常）：**
```javascript
const getCurrentCompetitionId = () => {
  const competitionId = localStorage.getItem('currentCompetitionId')
  return competitionId ? parseInt(competitionId) : 21
}

const filters = reactive({
  competitionId: getCurrentCompetitionId(),  // ✅ 有默认值
  ...
})
```

**OPS页面（错误）：**
```javascript
const filters = reactive({
  competitionId: null,  // ❌ 初始值为null
  status: '',
  ...
})

// 直接调用API，competitionId可能为空
const res = await filterRegistrations(params)
```

---

## ✅ 修复方案

### 方案：自动选择第一个赛事

**原理：** 
1. 先加载赛事列表
2. 如果没有选择赛事，自动选择第一个
3. 然后再加载报名列表

### 修复代码

**1. 修改 `loadCompetitions` 函数：**

```javascript
const loadCompetitions = async () => {
  try {
    const res = await getCompetitions()
    if (res.success) {
      competitions.value = res.data || []
      
      // 如果没有选择赛事且有可用赛事，自动选择第一个
      if (!filters.competitionId && competitions.value.length > 0) {
        filters.competitionId = competitions.value[0].id
        console.log('✅ 自动选择赛事:', competitions.value[0].name)
      }
    }
  } catch (error) {
    console.error('加载赛事失败:', error)
  }
}
```

**2. 修改 `loadRegistrations` 函数：**

```javascript
const loadRegistrations = async () => {
  // 如果没有选择赛事，不加载
  if (!filters.competitionId) {
    console.log('⚠️ 未选择赛事，跳过加载')
    return
  }
  
  loading.value = true
  try {
    const params = {
      competitionId: filters.competitionId,  // ✅ competitionId是必需参数
      page: currentPage.value - 1,
      size: pageSize.value
    }
    
    if (filters.status) params.status = filters.status
    if (filters.institutionName) params.institutionName = filters.institutionName
    if (filters.groupType) params.groupType = filters.groupType
    if (filters.projectName) params.projectName = filters.projectName
    
    const res = await filterRegistrations(params)
    // ...
  }
}
```

**3. 修改 `onMounted` 顺序：**

```javascript
onMounted(async () => {
  // 先加载赛事列表，再加载报名列表
  await loadCompetitions()
  // loadCompetitions会自动选择第一个赛事，然后才加载报名
  if (filters.competitionId) {
    loadRegistrations()
  }
})
```

**4. 优化提示信息：**

```vue
<!-- 没有赛事时的提示 -->
<el-alert
  v-if="competitions.length === 0 && !loading"
  title="暂无赛事"
  type="warning"
  :closable="false"
  style="margin: 20px 0"
>
  系统中还没有创建赛事，请先创建赛事后再查看报名列表
</el-alert>

<!-- 没有报名数据时的提示 -->
<el-alert
  v-else-if="registrations.length === 0 && !loading && filters.competitionId"
  title="暂无报名数据"
  type="info"
  :closable="false"
  style="margin: 20px 0"
>
  当前赛事暂无报名数据，请检查：1) 是否有参赛者报名 2) 筛选条件是否正确
</el-alert>
```

## 📝 技术细节

### API参数要求

**接口：** `GET /admin/registrations/filter`

**必需参数：**
- `competitionId` - 赛事ID（整数）
- `page` - 页码（从0开始）
- `size` - 每页数量

**可选参数：**
- `status` - 状态筛选
- `institutionName` - 机构名称筛选
- `groupType` - 竞赛组别筛选
- `projectName` - 项目名称筛选

### 为什么需要 competitionId

**后端设计原因：**
1. 报名数据按赛事组织
2. 避免一次加载所有赛事的报名
3. 提高查询性能
4. 符合业务逻辑（通常查看特定赛事的报名）

## ⚠️ 注意事项

### 1. 赛事选择器

**重要：** 用户必须先选择赛事才能查看报名列表

**用户体验优化：**
- 自动选择第一个赛事（无需手动选择）
- 赛事选择器置于筛选条件第一位
- 清晰的提示信息

### 2. 没有赛事的处理

**场景：** 新系统或测试环境可能没有赛事

**处理方式：**
- 显示警告提示
- 引导用户创建赛事
- 不发起API请求（避免错误）

### 3. localStorage依赖

**组委会页面：** 依赖 `localStorage.currentCompetitionId`  
**OPS页面：** 不依赖 localStorage，更灵活

**优点：**
- OPS可以自由切换查看不同赛事
- 不受组委会当前赛事影响
- 更符合管理员角色的需求
