# 参赛者登录后错误分析

## 问题总览

参赛者登录后出现以下错误和警告：

1. ❌ **赛事不存在 (400错误)**: `/api/competitions/21` 返回400，但不影响功能
2. ⚠️ **Element Plus API废弃警告**: `el-radio` 的 `label` 属性即将废弃
3. ⚠️ **Element Plus API废弃警告**: `el-link` 的 `underline` 布尔值即将废弃
4. ⚠️ **Ref元素未找到**: `updateTopScrollbarWidth` 找不到ref元素

---

## 问题1: 赛事不存在 (400错误)

### 错误信息
```
Failed to load resource: the server responded with a status of 400 (Bad Request)
❌ 加载赛事信息异常: AxiosError: Request failed with status code 400
```

### 问题根源

**文件**: `src/views/contestant/MyCompetition.vue`
**位置**: 第378行

```javascript
const competitionId = data.registration?.competitionId || localStorage.getItem('currentCompetitionId') || '21'
```

**问题**:
- 硬编码了默认值 `'21'` 作为fallback
- 如果 `registration.competitionId` 不存在且 `localStorage` 也没有 `currentCompetitionId`，就会尝试访问赛事21
- 赛事21可能不存在或已被删除，导致400错误

**影响范围**:
- 虽然报错，但由于使用了 `try-catch`（380-395行），不会中断整个页面加载
- 只是无法显示赛事信息（如阶段进度、时间线等）
- 其他功能（报名详情、评审结果等）正常工作

### 修改方案

**方案1: 移除硬编码的默认值**
```javascript
const competitionId = data.registration?.competitionId || localStorage.getItem('currentCompetitionId')
```
- 如果没有competitionId，就不加载赛事信息
- 需要在UI上处理 `competition.value` 为空的情况

**方案2: 改进错误处理**
```javascript
const competitionId = data.registration?.competitionId || localStorage.getItem('currentCompetitionId')
if (!competitionId) {
  console.warn('⚠️ 未找到赛事ID，跳过赛事信息加载')
  return
}
```
- 更明确地处理缺少competitionId的情况
- 避免发起无效的API请求

**推荐**: 方案2，更清晰且避免无效请求

## 问题4: updateTopScrollbarWidth 找不到ref元素

### 错误信息
```
❌ 找不到 ref 元素: Object { topScrollbar: undefined, tableContainer: undefined }
```

### 问题根源

**文件**: `src/views/committee/book/Registration.vue`
**位置**: 第895行

**出现场景**:
- 在 `onMounted` 钩子中通过 `setTimeout` 调用 `updateTopScrollbarWidth()`
- 此时表格可能还未渲染完成，ref还是undefined

### 相关代码
```javascript
onMounted(() => {
  loadDictionaries()
  loadRegistrations()
  
  // 初始化顶部滚动条 - 延迟确保表格渲染完成
  setTimeout(() => {
    updateTopScrollbarWidth()
    
    // 给表格内部的滚动容器添加滚动监听
    if (tableContainer.value) {
      const tableBody = tableContainer.value.querySelector('.el-table__body-wrapper')
      // ...
    }
  }, 300)
})
```

### 问题分析

1. **可能原因1**: 300ms延迟不够
   - 如果数据加载较慢或DOM渲染较慢，300ms可能不足
   
2. **可能原因2**: 条件渲染问题
   - 表格可能基于某个条件才渲染（如 `v-if="registrations.length > 0"`）
   - 如果初始数据为空，ref永远不会被创建

3. **可能原因3**: 数据未加载完成
   - `loadRegistrations()` 是异步的
   - setTimeout在数据返回前就执行了

### 修改方案

**方案1: 增加防护性检查**（最安全）
```javascript
const updateTopScrollbarWidth = () => {
  if (!topScrollbar.value || !tableContainer.value) {
    // 静默返回，不打印错误日志（避免干扰用户）
    return
  }
  const tableBody = tableContainer.value.querySelector('.el-table__body-wrapper')
  if (tableBody && topScrollbar.value) {
    const scrollContent = topScrollbar.value.querySelector('.top-scrollbar-content')
    if (scrollContent) {
      const tableWidth = tableBody.scrollWidth
      scrollContent.style.width = `${tableWidth}px`
    }
  }
}
```

**方案2: 等待数据加载完成**
```javascript
onMounted(async () => {
  loadDictionaries()
  await loadRegistrations()  // 等待数据加载
  
  // 数据加载后再初始化滚动条
  nextTick(() => {
    updateTopScrollbarWidth()
    // ...
  })
})
```

**方案3: 使用watchEffect自动响应**
```javascript
watchEffect(() => {
  if (registrations.value.length > 0) {
    nextTick(() => {
      updateTopScrollbarWidth()
    })
  }
})
```

**推荐**: 方案1（移除错误日志） + 方案2（等待数据加载），确保ref存在且不打印误导性错误。
