# 登录过期问题排查指南

## 问题描述
用户在使用过程中突然提示"登录已过期，请重新登录"。

## 可能原因

### 1. 后端 Token 过期时间设置过短
- 后端可能设置了较短的 JWT 过期时间（如 5 分钟、10 分钟）
- 建议后端设置合理的过期时间（如 2 小时或 4 小时）

### 2. 后端 API 返回 401 状态码
- 某些 API 接口验证 Token 失败
- Token 格式不正确
- 后端 Session 过期

### 3. 前端存储被清除
- 浏览器缓存被清空
- 用户手动清除了浏览器数据

## 已实施的优化

### 1. 防止重复跳转和弹窗
```javascript
// 使用 isRefreshing 标志防止重复处理 401
let isRefreshing = false
```

### 2. 增强的错误日志
在开发环境下，控制台会打印详细的错误信息：
- 🔴 401 未授权: 显示触发 401 的接口 URL 和 Token 前缀
- 🔴 403 无权限: 显示被拒绝的接口
- 🔴 404 未找到: 显示不存在的资源
- 🔴 服务器错误: 显示服务器返回的详细错误信息

### 3. Token 调试器（开发环境）
在页面右下角添加了一个浮动按钮，点击可查看：
- Token 状态（已登录/未登录）
- Token 内容预览
- 用户信息（JSON 格式）
- 当前路由
- 登录时间

**操作功能：**
- 复制 Token 到剪贴板
- 清除 Token（模拟登录过期）
- 刷新 Token（待实现）

## 排查步骤

### 步骤 1: 启用调试模式
1. 打开浏览器开发者工具（F12）
2. 切换到 Console 标签页
3. 在页面右下角找到蓝色 ℹ️ 按钮，点击查看 Token 状态

### 步骤 2: 重现问题
1. 重新登录系统
2. 记录登录时间
3. 正常使用系统功能
4. 当出现"登录已过期"提示时，立即查看控制台

### 步骤 3: 分析日志
查看控制台中的错误信息：

```
🔴 401 未授权: {
  url: "/api/xxx/yyy",
  token: "eyJhbGciOiJIUzI1NiIsI...",
  response: { ... }
}
```

记录以下信息：
- 触发 401 的接口 URL
- 从登录到过期的时间间隔
- 是否有规律性（如每次访问特定页面）

### 步骤 4: 验证后端配置
检查后端 JWT 配置：
```yaml
# application.yml 示例
jwt:
  secret: your-secret-key
  expiration: 7200000  # 2小时（毫秒）
```

建议后端开发人员检查：
1. JWT 过期时间设置
2. Token 验证逻辑
3. 是否有接口需要额外的权限验证

## 临时解决方案

### 方案 1: 增加 Token 过期时间
后端修改 JWT 配置，延长过期时间：
```java
// SecurityConfig.java
private static final long EXPIRATION_TIME = 7200000; // 2小时
// 或者
private static final long EXPIRATION_TIME = 14400000; // 4小时
```

### 方案 2: 实现 Token 自动刷新
前端可以在每次请求成功后，检查 Token 是否即将过期，自动刷新：

```javascript
// 伪代码示例
if (tokenWillExpireSoon()) {
  await refreshToken()
}
```

### 方案 3: 添加心跳检测
定时发送心跳请求，保持 Session 活跃：

```javascript
// 每 5 分钟发送一次心跳
setInterval(() => {
  api.heartbeat()
}, 5 * 60 * 1000)
```

## 常见问题

### Q1: 为什么会重复弹窗？
A: 多个并发请求同时返回 401 时，会触发多次错误处理。已通过 `isRefreshing` 标志解决。

### Q2: 清除 Token 后为什么还显示登录状态？
A: 可能是 Pinia Store 的状态未更新。建议刷新页面或使用 Token 调试器的"清除 Token"功能。

### Q3: 如何延长登录有效期？
A: 需要后端修改 JWT 配置中的 expiration 时间。
