## 🎯 核心算法实现

### 1. 数据加载和合并
```javascript
// 1. 并发获取书审和面谈排名
const [bookRes, interviewRes] = await Promise.all([
  getRankings({ competitionId, stage: 'BOOK' }),
  getRankings({ competitionId, stage: 'INTERVIEW' })
])

// 2. 通过 registrationId 合并数据
const projectMap = new Map()
bookData.forEach(item => {
  projectMap.set(item.registrationId, {
    ...item,
    bookScore: item.avgTotal,
    interviewScore: null
  })
})
interviewData.forEach(item => {
  const project = projectMap.get(item.registrationId)
  if (project) {
    project.interviewScore = item.avgTotal
  }
})
```

### 2. 综合得分计算
```javascript
compositeScore = bookScore × bookWeight% + interviewScore × interviewWeight%

// 示例：书审88分，面谈85.5分，权重各50%
compositeScore = 88 × 0.5 + 85.5 × 0.5 = 86.75分
```

### 3. 综合排名生成
```javascript
// 按综合得分降序排序
projects.sort((a, b) => {
  if (a.compositeScore === null) return 1  // 待面谈排最后
  if (b.compositeScore === null) return -1
  return b.compositeScore - a.compositeScore
})

// 分配排名
projects.forEach((p, index) => {
  if (p.compositeScore !== null) {
    p.rank = index + 1
  }
})
```

### 4. 批量设置入围
```javascript
// 1. 获取有综合得分的项目
let eligibleList = projects.filter(p => p.compositeScore !== null)

// 2. 应用最低分数线
if (minScore !== null) {
  eligibleList = eligibleList.filter(p => p.compositeScore >= minScore)
}

// 3. 计算入围数量
const shortlistCount = Math.ceil(eligibleList.length × ratio / 100)

// 4. 标记前N名为入围
eligibleList.slice(0, shortlistCount).forEach(p => {
  p.isShortlisted = true
  p.shortlistType = 'auto'
})
```

### 5. 个别增补/取消
```javascript
// 增补
project.isShortlisted = true
project.shortlistType = 'manual_add'

// 取消
project.isShortlisted = false
project.shortlistType = 'manual_remove'  // 如果原本是自动入围
// or
project.shortlistType = null  // 如果原本是手动增补
```

## 📊 数据流程

### 初始加载流程
```
1. 页面挂载
   ↓
2. 调用 loadData()
   ↓
3. 并发获取书审和面谈排名
   ├─ GET /api/admin/reviews/rankings?stage=BOOK
   └─ GET /api/admin/reviews/rankings?stage=INTERVIEW
   ↓
4. 合并数据（通过 registrationId）
   ↓
5. 计算综合得分（bookScore × 50% + interviewScore × 50%）
   ↓
6. 按综合得分排序
   ↓
7. 分配排名
   ↓
8. 渲染列表
```

### 调整权重流程
```
1. 用户修改权重（如 60% / 40%）
   ↓
2. 验证权重总和 = 100%
   ↓
3. 点击"应用权重"
   ↓
4. 重新计算所有项目的 compositeScore
   ↓
5. 重新排序
   ↓
6. 重新分配排名
   ↓
7. 刷新显示
```

### 批量设置入围流程
```
1. 选择入围比例（如 30%）
   ↓
2. 设置最低分数线（可选）
   ↓
3. 点击"批量设置入围"
   ↓
4. 计算入围数量: count = Math.ceil(eligibleCount × 30%)
   ↓
5. 过滤符合条件的项目（已完成书审和面谈 + 分数≥最低线）
   ↓
6. 弹出确认对话框
   ↓
7. 用户确认
   ↓
8. 重置所有入围状态
   ↓
9. 标记前N名为入围（shortlistType='auto'）
   ↓
10. 刷新显示
```

### 个别增补流程
```
1. 找到未入围的项目
   ↓
2. 点击"增补入围"按钮
   ↓
3. 修改状态:
   - isShortlisted = true
   - shortlistType = 'manual_add'
   ↓
4. 刷新显示（行变蓝色，状态显示"✅入围（增补）"）
```

## 🎯 使用指南

### 基本操作流程

#### 1. 查看综合排名
1. 登录组委会账号
2. 导航到：面谈阶段 → 入围管理
3. 等待数据加载
4. 查看综合排名列表

#### 2. 调整权重
1. 在"评分权重"区域修改书审和面谈的百分比
2. 确保总和为100%
3. 点击"应用权重"按钮
4. 查看更新后的综合得分和排名

#### 3. 批量设置入围（推荐流程）
1. **选择入围比例**: 选择30%/40%/50%，或自定义比例
2. **设置最低分数线**（可选）: 例如80分
3. **点击"批量设置入围"**: 
4. **确认提示**: 查看将入围的项目数量
5. **点击确定**: 系统自动标记前N名为入围
6. **查看结果**: 入围项目行变绿色，状态显示"✅入围"

#### 4. 个别增补入围
1. 在列表中找到未入围的项目（通常在排名靠后）
2. 点击该项目的"增补入围"按钮
3. 项目行变蓝色，状态显示"✅入围（增补）"
4. 统计区的"手动增补"数量+1

#### 5. 取消入围
1. 在列表中找到已入围的项目
2. 点击该项目的"取消入围"按钮
3. 项目行变红色，状态显示"❌未入围（取消）"
4. 统计区的"手动取消"数量+1

#### 6. 查看项目详情
1. 点击任意项目的"查看详情"按钮
2. 在对话框中查看：
   - 基本信息（排名、得分、组别、机构）
   - 书审评分（各维度得分 + 评委意见）
   - 面谈评分（各维度得分 + 评委意见）

#### 7. 导出入围名单
1. 完成入围设置后
2. 点击"导出入围名单"按钮
3. 自动下载CSV文件：`综合入围名单_2026-02-07.csv`
4. 用Excel打开查看

#### 8. 筛选和搜索
- **按组别筛选**: 选择基层组/进阶组/综合组
- **按项目名称搜索**: 输入关键词模糊匹配
- **按状态筛选**: 选择已入围/未入围/待面谈

## 💡 技术要点

### 1. 响应式数据管理
- 使用 `ref` 和 `computed` 管理响应式状态
- 所有计算逻辑封装在 `computed` 中，自动更新

### 2. 性能优化
- 使用 `Promise.all` 并发加载书审和面谈数据
- 筛选逻辑使用 `computed`，避免重复计算
- 列表渲染使用虚拟滚动（Element Plus Table）

### 3. 用户体验
- 加载状态指示器
- 操作确认对话框
- 友好的错误提示
- 颜色编码快速识别
- 图标辅助理解

### 4. 数据一致性
- 所有入围状态由客户端维护
- 权重调整立即生效
- 批量操作原子性（全部成功或全部失败）

## 🐛 已知限制

1. **入围状态不持久化**: 当前入围状态仅在客户端维护，刷新页面后会丢失。建议后续增加持久化API。

2. **详情API依赖**: 查看详情功能依赖 `GET /api/registrations/{id}` 返回 `reviewDetails` 字段。如果后端未提供，将只显示基本得分，无法显示各维度细分和评委意见。

3. **大数据量性能**: 当项目数量超过1000时，可能需要前端分页或后端分页支持。
