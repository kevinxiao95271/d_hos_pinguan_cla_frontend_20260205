# 机构搜索排序问题分析

## 📋 问题描述

**用户反馈**：
- 后端已经实现了按等级排序的逻辑（三级 > 二级 > 一级）
- 排序已应用到 `/api/institutions/search-v2` 接口
- 但前端注册页面搜索机构时，体验还不是按等级排序的

---

## 🔍 问题根因

### 前端使用的API

**文件**：`src/api/institution.js` 第76-83行

```javascript
export function searchInstitutions(data) {
  return request({
    url: '/institutions/search',    // ⚠️ 使用的是旧接口
    method: 'post',
    data,
    skipAuth: true
  })
}
```

**调用位置**：`src/components/InstitutionSelector.vue` 第246行

```javascript
const res = await searchInstitutions(params)
```

---

### 后端情况

**用户说明**：
- ✅ 后端已实现按等级排序：三级 > 二级 > 一级
- ✅ 排序已应用到 `/api/institutions/search-v2` 接口
- ❌ 旧接口 `/api/institutions/search` 可能没有更新排序逻辑

---

## 🎯 问题结论

### 核心问题

**前端调用的是旧接口 `/api/institutions/search`，而不是新接口 `/api/institutions/search-v2`**

```
前端 InstitutionSelector.vue
    ↓
调用 searchInstitutions()
    ↓
POST /api/institutions/search  ← ❌ 旧接口（无排序）
    ↓
后端返回未排序的结果
    ↓
前端显示：等级顺序混乱
```

**正确的流程应该是**：

```
前端 InstitutionSelector.vue
    ↓
调用 searchInstitutionsV2()  ← ✅ 需要新增
    ↓
POST /api/institutions/search-v2  ← ✅ 新接口（有排序）
    ↓
后端返回按等级排序的结果
    ↓
前端显示：三级 > 二级 > 一级
```

---

## ✅ 解决方案

### 方案1：修改前端API调用（推荐）

#### 步骤1：在 `src/api/institution.js` 中添加新接口

**位置**：第76-83行之后

```javascript
/**
 * 搜索机构（高性能，支持分页）
 * 公开接口，无需Token
 */
export function searchInstitutions(data) {
  return request({
    url: '/institutions/search',
    method: 'post',
    data,
    skipAuth: true
  })
}

/**
 * 搜索机构 V2（带等级排序）
 * 公开接口，无需Token
 */
export function searchInstitutionsV2(data) {
  return request({
    url: '/institutions/search-v2',  // ✅ 新接口
    method: 'post',
    data,
    skipAuth: true
  })
}
```

#### 步骤2：修改 `InstitutionSelector.vue` 使用新接口

**位置**：第135行（导入语句）

**修改前**：
```javascript
import { searchInstitutions, getCities, getDistricts, getAllLevels } from '@/api/institution'
```

**修改后**：
```javascript
import { searchInstitutionsV2, getCities, getDistricts, getAllLevels } from '@/api/institution'
```

**位置**：第246行（调用接口）

**修改前**：
```javascript
const res = await searchInstitutions(params)
```

**修改后**：
```javascript
const res = await searchInstitutionsV2(params)
```

### 方案2：直接替换旧接口（更简单）

**如果旧接口不再使用**，直接修改 `searchInstitutions` 函数的URL：

**文件**：`src/api/institution.js` 第76-83行

**修改前**：
```javascript
export function searchInstitutions(data) {
  return request({
    url: '/institutions/search',    // 旧接口
    method: 'post',
    data,
    skipAuth: true
  })
}
```

**修改后**：
```javascript
export function searchInstitutions(data) {

    data,
```

**优点**：
- ✅ 只需修改1处
- ✅ 组件代码无需改动

**前提**：
- 确认旧接口 `/institutions/search` 不再被其他地方使用
- 或者旧接口已废弃

### 后端排序逻辑（参考）

**预期的SQL排序**（伪代码）：
```sql
SELECT * FROM institution
WHERE name LIKE '%人民%' AND city = '杭州市'
ORDER BY 
  CASE level
    WHEN '三级甲等' THEN 1
    WHEN '三级乙等' THEN 2
    WHEN '三级丙等' THEN 3
    WHEN '二级甲等' THEN 4
    WHEN '二级乙等' THEN 5
    WHEN '二级丙等' THEN 6
    WHEN '一级甲等' THEN 7
    WHEN '一级乙等' THEN 8
    WHEN '一级丙等' THEN 9
    ELSE 10
  END,
  name ASC;
```
