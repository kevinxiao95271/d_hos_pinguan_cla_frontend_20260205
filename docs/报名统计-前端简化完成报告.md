### 地区分布

**显示内容**: 后端 `regionCounts` 的原始数据
- 如果后端返回 `{ "杭州": 17, "舟山": 15, ... }`，就显示这些
- 如果有"其他"或"未知地区"，也是后端数据，前端不做任何处理

### 主题类型分布

**显示内容**: 后端 `subjectTypeCounts` 的原始数据
- 如果后端返回 `{ "病人照护": 10, "其他": 6, ... }`，就显示这些
- "其他"是后端的分类，不是前端归类的

## ⚠️ 注意事项

### 1. 只显示最新赛事

由于 `/api/admin/stats/summary` 接口**不支持参数**，只能返回最新赛事（ID最大）的数据。

- ✅ 优点：逻辑简单，数据纯净
- ⚠️ 限制：无法查看历史赛事统计

### 2. 数据完全依赖后端

所有统计数据完全依赖后端返回：
- ✅ 优点：数据准确性由后端保证
- ⚠️ 限制：如果后端数据有问题，前端无法修正

### 3. "其他"分类的来源

**地区分布中的"其他"**: 来自后端 `regionCounts`
- 如果后端返回了"其他"，说明后端无法识别这些医院的地区
- 前端不再做任何处理

**主题类型中的"其他"**: 来自后端 `subjectTypeCounts`
- 这是后端的正常分类，表示不属于常见主题类型的项目

### 方案1：后端添加参数支持（推荐）

```java
@GetMapping("/stats/summary")
public ApiResponse<StatsSummaryResponse> summary(
    @RequestParam(required = false) Long competitionId
) {
    if (competitionId != null) {
        return ApiResponse.ok(statsService.summaryForCompetition(competitionId));
    }
    return ApiResponse.ok(statsService.summaryForLatestCompetition());
}
```
