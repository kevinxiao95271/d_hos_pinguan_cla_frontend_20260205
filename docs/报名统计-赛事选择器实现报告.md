# 报名统计-赛事选择器实现报告

## 📝 问题背景

**用户反馈**:
```
"2026年省级质量改进赛-2 统计数据加载成功"
但当前赛事明明是：2026浙江品管大赛
```

**问题原因**:
- `/api/admin/stats/summary` 接口设计为自动返回 **ID最大的赛事**（最新创建的赛事）
- 数据库中赛事情况：
  - 赛事ID 21：`2026浙江品管大赛`（2026-01-15创建）
  - 赛事ID 29：`2026年省级质量改进赛-2`（2026-02-05创建）← **ID最大，接口返回此赛事**

## ✅ 解决方案

添加**赛事选择器**，允许用户切换不同赛事的统计数据。

### 实现策略

采用**混合模式**：

1. **最新赛事**：使用 `getStatsSummary()` 
   - ✅ 有完整的后端统计数据
   - ✅ 包含地区分布、主题类型、评分雷达图

2. **历史赛事**：使用 `filterRegistrations()` + 前端计算
   - ✅ 支持任意赛事统计
   - ⚠️ 评分雷达图无数据（后端未返回评分）

### 默认行为

- 页面加载时默认选择 **赛事ID=21**（2026浙江品管大赛）
- 如果ID=21不存在，则选择列表中的第一个赛事

### 2. 状态管理

```javascript
const competitions = ref([])              // 赛事列表
const selectedCompetitionId = ref(null)   // 选中的赛事ID
const latestCompetitionId = ref(null)     // 最新赛事ID（用于判断用哪个接口）
```

### 3. 核心逻辑

#### loadCompetitions（加载赛事列表）

```javascript
const loadCompetitions = async () => {
  // 1. 获取赛事列表
  const res = await getCompetitions()
  competitions.value = res.data
  
  // 2. 默认选择ID=21的赛事
  const targetCompetition = competitions.value.find(c => c.id === 21)
  if (targetCompetition) {
    selectedCompetitionId.value = 21
  }
  
  // 3. 获取最新赛事ID
  const summaryRes = await getStatsSummary()
  latestCompetitionId.value = summaryRes.data.competitionId
  
  // 4. 加载选中赛事的数据
  await loadData()
}
```

#### loadData（加载统计数据）

```javascript
const loadData = async () => {
  // 判断选中的是最新赛事还是历史赛事
  if (selectedCompetitionId.value === latestCompetitionId.value) {
    // ✅ 最新赛事：使用后端统计接口
    const res = await getStatsSummary()
    const summaryData = res.data
    
    // 直接使用后端数据
    stats.totalRegistrations = summaryData.registrationCount
    // regionCounts, subjectTypeCounts, avgPlan...
    
    initCharts(summaryData)
  } else {
    // ⚠️ 历史赛事：前端计算统计
    const res = await filterRegistrations({ 
      competitionId: selectedCompetitionId.value 
    })
    const registrations = res.data
    
    // 前端计算统计数据
    stats.totalRegistrations = registrations.length
    stats.basicGroup = registrations.filter(r => r.groupType === 'BASIC').length
    
    // 前端计算地区分布
    const regionCounts = {}
    registrations.forEach(r => {
      // 关键词匹配识别地区
    })
    
    // 前端计算主题类型
    const subjectTypeCounts = {}
    registrations.forEach(r => {
      const subject = r.subjectTypeLabel || '未知'
      subjectTypeCounts[subject]++
    })
    
    // 构造统一的数据结构
    const summaryData = {
      regionCounts,
      subjectTypeCounts,
      avgPlan: 0,  // 历史赛事无评分数据
      avgProblem: 0,
      // ...
    }
    
    initCharts(summaryData)
  }
}
```

#### handleCompetitionChange（切换赛事）

```javascript
const handleCompetitionChange = () => {
  loadData()  // 重新加载数据
}
```

## 📊 数据对比

### 最新赛事（使用 getStatsSummary）

| 数据项 | 来源 | 准确性 |
|-------|------|--------|
| 总报名数 | `summaryData.registrationCount` | ✅ 后端统计 |
| 地区分布 | `summaryData.regionCounts` | ✅ 后端维护 |
| 主题类型 | `summaryData.subjectTypeCounts` | ✅ 后端维护 |
| 评分雷达图 | `summaryData.avgPlan`等 | ✅ 后端计算 |
| 组别统计 | ⚠️ 后端暂缺 | ⚠️ 显示0 |

### 历史赛事（使用 filterRegistrations + 前端计算）

| 数据项 | 来源 | 准确性 |
|-------|------|--------|
| 总报名数 | `registrations.length` | ✅ 准确 |
| 地区分布 | 前端关键词匹配 | ⚠️ 可能不准确 |
| 主题类型 | 前端遍历统计 | ✅ 准确 |
| 评分雷达图 | ❌ 无数据 | ❌ 全为0 |
| 组别统计 | `filter(r => r.groupType)` | ✅ 准确 |

## ⚠️ 注意事项

### 1. 历史赛事的限制

当选择历史赛事时：

- ✅ **可以显示**：总报名数、组别分布、地区分布、主题类型
- ⚠️ **地区分布可能不准确**：使用前端关键词匹配，不如后端的 institutionRegion 准确
- ❌ **评分雷达图全为0**：后端只为最新赛事提供评分统计

### 2. 性能考虑

- **最新赛事**：1次API调用（`getStatsSummary`）
- **历史赛事**：1次API调用（`filterRegistrations`）+ 前端计算

历史赛事如果报名数量大（如1000+条），前端计算可能有短暂延迟。

### 3. 默认选择逻辑

```javascript
// 优先选择ID=21
const targetCompetition = competitions.value.find(c => c.id === 21)
if (targetCompetition) {
  selectedCompetitionId.value = 21
} else if (competitions.value.length > 0) {
  // 如果ID=21不存在，选择第一个
  selectedCompetitionId.value = competitions.value[0].id
}
```

## 🐛 已知问题

### 问题1：组别统计在最新赛事中显示为0

**原因**: 后端 `getStatsSummary` 未返回 `basicCount`、`comprehensiveCount`、`advancedCount`

**解决方案**:
- 短期：保持现状，提示"待后端补充字段"
- 长期：请后端添加这3个字段

### 问题2：历史赛事的地区分布不够准确

**原因**: 前端使用关键词匹配机构名称来识别地区

**解决方案**:
- 短期：使用现有逻辑，在UI上标注"基于机构名称估算"
- 长期：后端在 `filterRegistrations` 返回数据中包含 `institutionRegion` 字段

## 🚀 后续优化建议

### 1. 后端优化（推荐）

**建议后端修改 `/api/admin/stats/summary` 接口**:

```java
// 添加可选的 competitionId 参数
@GetMapping("/stats/summary")
public ApiResponse<StatsSummaryResponse> summary(
    @RequestParam(required = false) Long competitionId
) {
    if (competitionId != null) {
        // 返回指定赛事的统计
        return ApiResponse.ok(statsService.summaryForCompetition(competitionId));
    }
    // 返回最新赛事的统计
    return ApiResponse.ok(statsService.summaryForLatestCompetition());
}
```

**优点**:
- 前端无需维护两套逻辑
- 所有赛事都能获得完整的后端统计数据
- 评分雷达图对所有赛事都可用

### 2. 前端优化

**缓存赛事列表**:
```javascript
// 避免每次页面加载都重新获取赛事列表

// 记住用户上次选择的赛事
const lastSelectedId = localStorage.getItem('lastSelectedCompetitionId')

}
```
