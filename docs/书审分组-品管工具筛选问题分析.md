# 书审分组 - 品管工具筛选问题分析

## 问题描述

用户反馈：在书审分组界面，使用"品管工具"下拉框进行筛选时，筛选功能不起作用，结果始终显示全部数据。

---

## 测试环境

- **前端页面**: `src/views/committee/book/Registration.vue` (书审分组/项目分组)
- **后端API**: `GET /api/admin/registrations/filter`
- **测试数据**: 总计63条报名数据

---

## 问题根因分析

### 1. 前端实现 (`src/views/committee/book/Registration.vue`)

#### **筛选器绑定** (第54-63行)

```vue
<el-form-item label="品管工具">
  <el-select v-model="filters.methodLabel" placeholder="全部" clearable style="width: 180px">
    <el-option
      v-for="item in dictionaries.methods"
      :key="item.code"
      :label="item.label"
      :value="item.label"
    />
  </el-select>
</el-form-item>
```

**问题**:
- 绑定到 `filters.methodLabel`
- `value` 使用 `item.label` （中文标签，如"品管圈-问题解决"、"5S"）

#### **filters定义** (第520-527行)

```javascript
const filters = reactive({
  competitionId: getCurrentCompetitionIdSync(),
  institutionName: '',
  groupType: '',
  groupCode: '',
  projectName: '',
  methodLabel: ''  // ⬅️ 使用 methodLabel
})
```

#### **API调用** (第690-696行)

```javascript
const loadRegistrations = async () => {
  loading.value = true
  try {
    const res = await filterRegistrations({
      ...filters,  // ⬅️ 直接展开filters，包含 methodLabel
      ...getPaginationParams()
    })
    // ...
  }
}
```

**实际传递给后端的参数**:
```javascript
{
  competitionId: 1,
  methodLabel: "品管圈-问题解决",  // ⬅️ 中文标签
  page: 0,
  size: 50
}
```

#### **额外Bug: resetFilters** (第714-722行)

```javascript
const resetFilters = () => {
  filters.institutionName = ''
  filters.groupType = ''
  filters.groupCode = ''
  filters.projectName = ''
  filters.methodCode = ''  // ⬅️ 错误！filters中没有methodCode，应该是methodLabel
  resetPagination()
  loadRegistrations()
}
```

### 2. 后端API测试结果

#### **测试1: 无筛选参数**

```bash
GET /api/admin/registrations/filter?competitionId=1&page=0&size=10
```

**结果**: ✅ 返回 **63条** 数据

---

#### **测试2: 使用 methodCode (代码)**

```bash
GET /api/admin/registrations/filter?competitionId=1&methodCode=method_1&page=0&size=10
```

**结果**: ✅ 返回 **0条** 数据

**说明**: 
- 筛选生效了（数量变少了）
- 但没有匹配数据（因为 `method_1` 在当前数据中不存在）

---

#### **测试3: 使用 methodLabel (标签)**

```bash
GET /api/admin/registrations/filter?competitionId=1&methodLabel=品管圈-问题解决&page=0&size=10
```

**结果**: ❌ 返回 **63条** 数据（与无筛选相同）

**说明**: 
- 筛选完全无效
- 后端忽略了 `methodLabel` 参数

---

### 3. 实际数据库存储

从API返回的数据看，数据库存储的字段值：

| registrationId | projectName | methodCode | methodLabel |
|---|---|---|---|
| ... | 测试项目9461 | `5s` | `5S` |
| ... | 满意度-流程改造-杭州天目山医院-2 | `method_15` | `流程改造` |
| ... | 安全环境-六西格玛管理-杭州天目山医院-6 | `method_11` | `六西格玛管理` |

**关键发现**:
- 数据库同时存储 `methodCode` 和 `methodLabel`
- `methodCode` 是唯一标识（如 `5s`, `method_15`, `method_11`）
- `methodLabel` 是显示名称（如 `5S`, `流程改造`, `六西格玛管理`）

## 结论

### ✅ 后端实现正确

- 后端API支持 `methodCode` 参数进行筛选
- 筛选逻辑工作正常
- 后端不支持（或忽略）`methodLabel` 参数

### ❌ 前端实现错误

**错误1**: 参数名不匹配
- 前端使用: `methodLabel`（标签）
- 后端期望: `methodCode`（代码）

**错误2**: 参数值类型不匹配
- 前端传递: 中文标签（`"品管圈-问题解决"`）
- 后端期望: 代码（`"method_1"`）

**错误3**: resetFilters bug
- 第719行：`filters.methodCode = ''`
- 应该是：`filters.methodLabel = ''`

## 修复方案

### 方案1: 改为使用 methodCode（推荐）

**优点**:
- 与后端API一致
- 与面谈分组页面一致
- 代码维护性好

**改动点**:

#### 1. 修改select绑定 (第54-63行)

```vue
<!-- 修改前 -->
<el-select v-model="filters.methodLabel" placeholder="全部" clearable style="width: 180px">
  <el-option
    v-for="item in dictionaries.methods"
    :key="item.code"
    :label="item.label"
    :value="item.label"
  />
</el-select>

<!-- 修改后 -->
<el-select v-model="filters.methodCode" placeholder="全部" clearable style="width: 180px">
  <el-option
    v-for="item in dictionaries.methods"
    :key="item.code"
    :label="item.label"
    :value="item.code"
  />
</el-select>
```

#### 2. 修改filters定义 (第526行)

```javascript
// 修改前
methodLabel: ''

// 修改后
methodCode: ''
```

#### 3. 修改筛选标签显示 (第119-126行)

```vue
<!-- 修改前 -->
<el-tag
  v-if="filters.methodLabel"
  closable
  @close="filters.methodLabel = ''; loadRegistrations()"
  type="info"
  style="margin-right: 8px"
>
  品管工具：{{ filters.methodLabel }}
</el-tag>

<!-- 修改后 -->
<el-tag
  v-if="filters.methodCode"
  closable
  @close="filters.methodCode = ''; loadRegistrations()"
  type="info"
  style="margin-right: 8px"
>
  品管工具：{{ getMethodLabel(filters.methodCode) }}
</el-tag>
```

#### 4. 修改hasActiveFilters计算属性 (第572行)

```javascript
// 修改前
filters.methodLabel

// 修改后
filters.methodCode
```

#### 5. 修改resetFilters (第719行)

```javascript
// 修改前（已经是 methodCode，但与filters定义不一致）
filters.methodCode = ''

// 保持为
filters.methodCode = ''
```

#### 6. 确保getMethodLabel函数存在 (第598-601行)

```javascript
// 已存在，用于code转label
const getMethodLabel = (code) => {
  const method = dictionaries.methods.find(m => m.code === code)
  return method ? method.label : code
}
```

## 总结

**问题**: 前端使用 `methodLabel`（中文标签）作为筛选参数，但后端API期望 `methodCode`（唯一代码）

**根本原因**: 前端开发时可能参考了其他字段（如 `subjectTypeLabel`），但品管工具字段的API设计使用的是 `code`

**解决方案**: 将前端筛选参数从 `methodLabel` 改为 `methodCode`，保持与后端API和面谈分组页面一致

**预期效果**: 品管工具筛选功能正常工作，用户可以按品管工具类型筛选报名项目
