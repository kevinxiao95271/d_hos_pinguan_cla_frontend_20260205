## 🎯 问题分析

### 问题1：新接口需要认证

**影响**:
- ❌ 注册页面是**公开页面**，用户还未登录
- ❌ 如果切换到 `search-v2`，注册页面将无法搜索机构
- ❌ 用户无法完成注册流程

**场景**:
```
用户打开注册页面
    ↓
选择机构（未登录状态）
    ↓
前端调用 /api/institutions/search-v2
    ↓
后端返回 401 Unauthorized ❌
    ↓
搜索失败，无法注册
```

---

### 问题2：旧接口没有排序

**测试结果显示**:
- 搜索"杭州 人民"
- 返回的全是"未定级"机构
- 三级医院没有排在前面

**期望的排序**:
1. 浙江大学医学院附属第一医院 - **三级甲等**
2. 杭州市第一人民医院 - **三级乙等**（或二级甲等）
3. 建德市第一人民医院 - **二级**
4. 未定级医院 - **未定级**

**实际的排序**:
1. 中国人民健康保险... - **未定级**
2. 中国人民武装警察... - **未定级**
3. 中国人民解放军... - **未定级**
...（全是未定级）

---

## 💡 解决方案

### 方案A：后端将 search-v2 设置为公开接口（推荐 ⭐⭐⭐⭐⭐）

**操作**: 后端修改 `search-v2` 接口权限，允许未认证访问

**后端伪代码**:
```java
@PostMapping("/search-v2")
@AllowAnonymous  // ✅ 添加此注解，允许匿名访问
public ResponseEntity<?> searchV2(@RequestBody SearchRequest request) {
    // ... 带排序的搜索逻辑
}
```

**优点**:
- ✅ 前端只需修改1行代码（URL改为 search-v2）
- ✅ 注册页面可以正常使用
- ✅ 搜索结果按等级排序

**前端修改**:
```javascript
// src/api/institution.js 第78行
url: '/institutions/search-v2'  // 改为v2
```

---

### 方案B：后端给旧接口添加排序逻辑（次选 ⭐⭐⭐⭐）

**操作**: 后端在 `search` 接口中也添加等级排序

**后端伪代码**:
```java
@PostMapping("/search")
@AllowAnonymous
public ResponseEntity<?> search(@RequestBody SearchRequest request) {
    // ✅ 添加排序逻辑
    return institutionService.searchWithSort(request);
}
```

**优点**:
- ✅ 前端无需修改任何代码
- ✅ 注册页面自动应用排序
- ✅ 兼容性最好

**缺点**:
- ⚠️ 需要重复实现排序逻辑（如果v2已经实现）

---

### 方案C：前端区分场景使用不同接口（不推荐 ⭐⭐）

**思路**: 
- 注册页面：使用旧接口 `search`（公开）
- 后台管理：使用新接口 `search-v2`（需认证，有排序）

**缺点**:
- ❌ 注册页面依然没有排序
- ❌ 代码复杂度增加
- ❌ 用户体验差

---

## 📋 后端需要确认的问题

### 问题1：search-v2 为什么需要认证？

**可能的原因**:
1. 后端忘记设置为公开接口
2. 有意设计为需要认证（但这不合理，因为注册场景需要公开）
3. Spring Security配置问题

**建议**: 
- 如果 `search-v2` 是为了替代 `search`，应该设置为公开接口
- 如果 `search-v2` 只用于后台管理，应该保持旧接口 `search` 的排序功能

---

### 问题2：为什么旧接口没有排序？

**测试结果**:
- 搜索"杭州 人民"返回48条
- 前5条全是"未定级"
- 没有看到三级医院

**可能的原因**:
1. 旧接口确实没有排序逻辑
2. 排序逻辑只在 `search-v2` 中实现
3. 或者排序有问题（"未定级"被排在了前面？）

**建议**: 
- 检查旧接口的SQL查询，看看 ORDER BY 子句
- 或者统一将排序逻辑应用到两个接口

## 🎯 结论

### 🔴 不能直接切换

**原因**:
1. ❌ 新接口 `search-v2` 返回 401，需要认证
2. ❌ 注册页面是公开页面，用户未登录
3. ❌ 切换后会导致注册流程崩溃

### ✅ 需要后端配合

**两个选择**:
1. **后端将 `search-v2` 设置为公开接口** → 前端改URL
2. **后端给 `search` 添加排序逻辑** → 前端不用改
