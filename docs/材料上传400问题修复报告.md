# 材料上传400问题修复报告

## 问题回顾

参赛者（手机号：13100009911）在提交报名材料时遇到错误：
- 初始错误：404 Not Found `/materials/upload/131`
- 修复路径后：400 Bad Request `/registrations/131/materials`

---

## 根本原因

通过系统测试发现，后端API实际需要的字段与文档不一致：

### 文档中的定义（不准确）

```javascript
FormData: {
  materialType: "REGISTRATION_FORM",  // ❌ 实际字段名不对
  file: <File>
}
```

### 后端实际需要的字段

```javascript
FormData: {
  file: <File>,              // ✅ 文件对象
  type: "REGISTRATION_FORM", // ✅ 材料类型（不是materialType）
  contentType: "application/vnd.openxmlformats-officedocument.wordprocessingml.document"  // ✅ 必需字段
}
```

**关键发现：**
1. 字段名是 `type` 而不是 `materialType`
2. 必须提供 `contentType` 字段（文件的MIME类型）
3. 如果只传 `materialType`，后端返回标准400错误
4. 如果只传 `type`，后端返回明确错误："content type must not be null."

---

## 测试验证

### 测试结果对比

| 字段组合 | 状态码 | 结果 |
|---|---|---|
| `file + materialType` | 400 | ❌ 字段名错误 |
| `file + type` | 400 | ❌ 缺少contentType |
| `file + type + contentType` | 200 | ✅ 上传成功 |

## 技术细节

### contentType的获取

- **浏览器File对象**：`file.type` 属性包含MIME类型
- **常见MIME类型**：
  - `.docx`: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
  - `.pdf`: `application/pdf`
  - `.zip`: `application/zip`
  - `.rar`: `application/x-rar-compressed`
  - `.jpg`: `image/jpeg`
  - `.png`: `image/png`
- **后备方案**：如果`file.type`为空，使用 `application/octet-stream`
