# 字典数据重复问题 - 后端修复指南

## 问题现象

前端报名页面的4个下拉框出现**相同选项重复两次**：
- 主题类型
- 运用手法
- 改善就医感受
- 医疗质量安全主题

## 问题原因

数据库 `dictionaries` 表中存在两套数据：

### 新版数据（语义化code）
```
code: case_quality, label: 病例质量
code: cost_efficiency, label: 成本效益
code: appointment, label: 预约挂号服务更加便捷
```

### 旧版数据（编号式code）
```
code: subject_type_2, label: 病例质量
code: subject_type_4, label: 成本效益
code: appointment_service, label: 预约挂号服务更加便捷
```

**结果：** label相同，code不同，导致前端下拉框显示重复选项。

## 修复方案

### 方案1：删除旧数据（推荐）

**保留语义化code，删除编号式code：**

```sql
-- 主题类型
DELETE FROM dictionaries WHERE type = 'subject_type' AND code LIKE 'subject_type_%';

-- 运用手法
DELETE FROM dictionaries WHERE type = 'method' AND code LIKE 'method_%';

-- 改善就医感受：需要手动删除以下旧code
DELETE FROM dictionaries WHERE code IN (
  'appointment',
  'environment',
  'internet_diagnosis',
  'post_discharge',
  'pre_in_out'
);

-- 医疗质量安全主题：需要手动删除以下旧code
DELETE FROM dictionaries WHERE code IN (
  'stroke',
  'key_diagnosis_record',
  'tnm',
  'perioperative_mortality',
  'stemi',
  'sepsis_bundle',
  'vte',
  'level4_surgery_mdt',
  'adverse_event_report'
);
```

**执行前检查：**
```sql
-- 检查是否有报名数据使用了这些旧code
SELECT 
  r.id,
  r.project_name,
  ai.subject_type_code,
  ai.method_code,
  ai.experience_improve_code,
  ai.quality_topic_code
FROM registrations r
LEFT JOIN activity_info ai ON r.id = ai.registration_id
WHERE 
  ai.subject_type_code LIKE 'subject_type_%'
  OR ai.method_code LIKE 'method_%'
  OR ai.experience_improve_code IN ('appointment', 'environment', 'internet_diagnosis', 'post_discharge', 'pre_in_out')
  OR ai.quality_topic_code IN ('stroke', 'key_diagnosis_record', 'tnm', 'perioperative_mortality', 'stemi', 'sepsis_bundle', 'vte', 'level4_surgery_mdt', 'adverse_event_report');
```

**如果有数据使用旧code，需要先迁移：**
```sql
-- 示例：迁移 subject_type 数据
UPDATE activity_info SET subject_type_code = 'patient_care' WHERE subject_type_code = 'subject_type_1';
UPDATE activity_info SET subject_type_code = 'case_quality' WHERE subject_type_code = 'subject_type_2';
-- 依此类推...
```

### 方案2：停用旧数据

**将旧版数据标记为停用：**

```sql
-- 主题类型
UPDATE dictionaries SET active = false WHERE type = 'subject_type' AND code LIKE 'subject_type_%';

-- 运用手法
UPDATE dictionaries SET active = false WHERE type = 'method' AND code LIKE 'method_%';

-- 改善就医感受
UPDATE dictionaries SET active = false WHERE code IN (
  'appointment',
  'environment',
  'internet_diagnosis',
  'post_discharge',
  'pre_in_out'
);

-- 医疗质量安全主题
UPDATE dictionaries SET active = false WHERE code IN (
  'stroke',
  'key_diagnosis_record',
  'tnm',
  'perioperative_mortality',
  'stemi',
  'sepsis_bundle',
  'vte',
  'level4_surgery_mdt',
  'adverse_event_report'
);
```

**同步修改API，只返回active=true的数据：**

Java示例：
```java
@GetMapping("/dictionaries/{type}")
public ResponseEntity<ApiResponse<List<Dictionary>>> getDictionaries(@PathVariable String type) {
    List<Dictionary> dictionaries = dictionaryService.findByTypeAndActive(type, true);
    return ResponseEntity.ok(ApiResponse.success(dictionaries));
}
```

Repository示例：
```java
List<Dictionary> findByTypeAndActive(String type, Boolean active);
```

## ⚠️ 重要：统一"其他"选项的code

**前端已统一所有"其他"选项的判断逻辑为 `code === 'other'`**

**后端必须确保4个字典类型的"其他"选项，code统一为 `'other'`：**

```sql
-- 1. 检查当前"其他"选项的code
SELECT type, code, label FROM dictionaries 
WHERE label LIKE '%其他%' OR label = '其他' OR code LIKE '%other%'
ORDER BY type, code;

-- 2. 统一"其他"选项的code为 'other'
-- 主题类型：如果存在 subject_type_11，改为 'other'
UPDATE dictionaries SET code = 'other' 
WHERE type = 'subject_type' AND (code = 'subject_type_11' OR (label LIKE '%其他%' AND code != 'other'));

-- 3. 确保没有重复的 'other' code（同一type下只能有一个）
-- 如果有多个，保留一个，删除其他
```

**修复后的预期结果：**
```
type: 'subject_type',        code: 'other', label: '其他'
type: 'method',              code: 'other', label: '其他'
type: 'experience_improve',  code: 'other', label: '其他（或其他相关表述）'
type: 'quality_topic',       code: 'other', label: '其他'
```

## 修复步骤总结

1. **备份数据库**（重要！）
2. **统一"其他"选项code为`'other'`**（必须！前端已移除 `subject_type_11` 判断）
3. **检查是否有数据使用旧code**（执行上面的SELECT查询）
4. **如有使用，先执行数据迁移**（UPDATE语句）
5. **删除或停用旧数据**（DELETE或UPDATE active=false）
6. **如选择方案2，修改API逻辑**（只返回active=true）
7. **前端测试验证**（刷新报名页面，确认下拉框无重复且"其他"选项正常）
