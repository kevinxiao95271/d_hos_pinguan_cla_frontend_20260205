## 问题现象

1. 在书审分组页面选择"基层组"

3. 查看结果
4. 清除筛选条件，查询全部

## 根本原因

### 🔴 后端API Bug（已确认）

**接口：** `POST /api/admin/registrations/auto-group`

**Bug描述：** 后端API**完全忽略**了请求参数中的`groupType`字段

**实际行为：**
```java
// 伪代码 - 后端当前的错误实现
public void autoGroup(AutoGroupRequest request) {
    // ❌ 错误：查询该赛事的所有项目，没有按groupType筛选
    List<Registration> allRegistrations = registrationRepo
        .findByCompetitionId(request.getCompetitionId());
    
    // ❌ 错误：对所有项目进行分组，不管它们的groupType是什么
    int groupNumber = 1;
    int count = 0;
    for (Registration reg : allRegistrations) {
        reg.setGroupCode(request.getGroupPrefix() + groupNumber);
        count++;
        if (count % request.getGroupSize() == 0) {
            groupNumber++;
        }
    }
    
    registrationRepo.saveAll(allRegistrations);
}
```

**期望行为：**
```java
// 伪代码 - 正确实现
public void autoGroup(AutoGroupRequest request) {
    // ✅ 正确：只查询指定groupType的项目
    List<Registration> registrations = registrationRepo
        .findByCompetitionIdAndGroupType(
            request.getCompetitionId(),
            request.getGroupType()  // ⚠️ 关键：添加groupType筛选
        );
    
    // ✅ 正确：只对这些项目进行分组
    int groupNumber = 1;
    int count = 0;
    for (Registration reg : registrations) {
        reg.setGroupCode(request.getGroupPrefix() + groupNumber);
        count++;
        if (count % request.getGroupSize() == 0) {
            groupNumber++;
        }
    }
    
    registrationRepo.saveAll(registrations);
}
```

## 影响分析

### 用户看到的现象

1. **第一次操作**：对基层组执行自动分组
   - 结果：所有项目都被分配到A组（A1-A5）
   - 基层组看起来正常，但综合组和进阶组都被污染了

2. **第二次操作**：对综合组执行自动分组
   - 结果：所有项目都被重新分配到B组（B1-B5）
   - 综合组看起来正常，但基层组和进阶组都被污染了

3. **第三次操作**：对进阶组执行自动分组
   - 结果：所有项目都被重新分配到C组（C1-C5）
   - 进阶组看起来正常，但基层组和综合组都被污染了

**这就是为什么用户看到"基层组都落到了C1 C2"的原因！**
- 最后一次操作可能是对进阶组执行了自动分组
- 导致所有项目（包括基层组）都被分配到了C组

## 结论

### ❌ 这是后端API的问题

**问题接口：** `POST /api/admin/registrations/auto-group`

**Bug详情：**
- 后端完全忽略了`groupType`参数
- 对该赛事的所有项目进行分组，不管它们的组别
- 导致跨组别分组编号混乱

**测试证据：**
- 请求参数：`groupType=BASIC`（只处理基层组）
- 实际行为：处理了所有123个项目（包括综合组38人、进阶组42人）
- 响应数据：明确返回了所有被修改的项目，包括其他组别

### ✅ 前端代码正常

- ✅ 前端正确传递了所有参数（`competitionId`, `groupType`, `groupPrefix`, `groupSize`）
- ✅ 前端的prefixMap映射正确（BASIC→A, COMPREHENSIVE→B, ADVANCED→C）
- ✅ 前端无需修改
