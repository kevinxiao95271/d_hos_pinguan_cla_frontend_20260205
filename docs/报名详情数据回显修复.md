# 报名详情数据回显修复

## 📋 问题描述

**现象**：编辑报名草稿时，赛事选择无法正确回显

**用户反馈**：
> 编辑报名草稿时，赛事信息需要从 `data.data.competitionId` 获取，而不是从 `data.data.registration.competitionId`

---

## 🔍 问题分析

### 后端API响应结构

根据实际测试，`GET /api/registrations/{id}` 可能返回两种结构：

**结构1：competitionId在顶层**
```json
{
  "success": true,
  "data": {
    "competitionId": 1,           ← 在顶层
    "competitionName": "2026浙江省品管大赛",
    "registration": {
      "id": 5,
      "projectName": "测试项目",
      "groupType": "BASIC",
      "status": "DRAFT"
    },
    "institution": { ... },
    "members": [ ... ],
    "activityInfo": { ... }
  }
}
```

**结构2：competitionId在registration中**
```json
{
  "success": true,
  "data": {
    "registration": {
      "id": 5,
      "competitionId": 1,         ← 在registration中
      "projectName": "测试项目",
      "groupType": "BASIC",
      "status": "DRAFT"
    },
    "institution": { ... },
    "members": [ ... ]
  }
}
```

### 原代码问题

**修复前的代码**：
```javascript
const loadRegistrationDetail = async () => {
  try {
    const res = await getRegistrationDetail(registrationId.value)
    if (res.success && res.data) {
      const registration = res.data.registration || res.data
      
      // ❌ 只从 registration 中取值
      form.basic.competitionId = registration.competitionId
      form.basic.projectName = registration.projectName
      form.basic.groupType = registration.groupType
      
      // ...
    }
  } catch (error) {
    console.error('加载报名详情失败:', error)
  }
}
```

**问题**：
- 如果 `competitionId` 在顶层 `data.competitionId`
- 而代码只从 `registration.competitionId` 取值
- 会导致 `form.basic.competitionId = undefined`
- 表单中的赛事下拉框显示为空 ❌

---

## ✅ 解决方案

### 兼容两种响应结构

**修复后的代码**：
```javascript
const loadRegistrationDetail = async () => {
  try {
    const res = await getRegistrationDetail(registrationId.value)
    if (res.success && res.data) {
      // 适配后端响应结构
      const data = res.data
      const registration = data.registration || data
      
      // 状态
      form.status = registration.status
      
      // 基本信息
      // ✅ competitionId 可能在顶层或在registration中
      form.basic.competitionId = data.competitionId || registration.competitionId
      form.basic.projectName = registration.projectName
      form.basic.groupType = registration.groupType
      
      console.log('📝 加载报名详情:', {
        competitionId: form.basic.competitionId,
        projectName: form.basic.projectName,
        groupType: form.basic.groupType
      })
      
      // 成员信息
      if (data.members && data.members.length > 0) {
        form.members.participants = data.members.filter(m => m.role === 'PARTICIPANT')
        form.members.mentors = data.members.filter(m => m.role === 'MENTOR')
      }
      
      // 活动说明
      if (data.activityInfo) {
        Object.assign(form.activity, data.activityInfo)
      }
      
      // 项目总结
      if (data.projectSummary) {
        Object.assign(form.summary, data.projectSummary)
      }
    }
  } catch (error) {
    console.error('加载报名详情失败:', error)
    ElMessage.error('加载报名详情失败')
  }
}
```

### 核心改进

**关键逻辑**：
```javascript
// 优先从顶层获取，如果没有再从registration中获取
form.basic.competitionId = data.competitionId || registration.competitionId
```

**优先级**：
1. 先尝试从 `data.competitionId`（顶层）
2. 如果不存在，再从 `registration.competitionId`
3. 确保两种结构都能正确处理

**调试日志**：
```javascript
console.log('📝 加载报名详情:', {
  competitionId: form.basic.competitionId,
  projectName: form.basic.projectName,
  groupType: form.basic.groupType
})
```
- 添加日志，方便在浏览器控制台查看加载的值
- 帮助快速定位数据回显问题

## 🔍 调试技巧

### 如果赛事仍然不显示

**检查步骤**：

1. **打开浏览器开发者工具（F12）**
   - 切换到 Console 标签
   - 查看是否有错误信息

2. **检查API响应**
   - 切换到 Network 标签
   - 找到 `GET /api/registrations/{id}` 请求
   - 点击查看 Response
   - 确认 `competitionId` 的位置：
     - 在 `data.competitionId`？
     - 还是在 `data.registration.competitionId`？

3. **检查控制台日志**
   ```
   📝 加载报名详情: { ... }
   ```
   - 如果 `competitionId: undefined` → 数据获取有问题
   - 如果 `competitionId: 1` → 数据获取正确，可能是下拉框渲染问题

4. **检查赛事列表是否加载**
   - 在控制台输入：`window.$nuxt?.$root?.$children?.[0]?.competitions`
   - 或直接在 Vue DevTools 中查看 `competitions` 数据
   - 确认赛事列表已加载，且包含 `id: 1` 的赛事

### 1. 后端API设计建议

**推荐统一响应结构**：
```json
{
  "success": true,

    "registration": {              ← 或者不需要嵌套
      // ...其他详细信息
    },
    "institution": { ... },
    "members": [ ... ]
  }
}
```

**好处**：
- ✅ 结构清晰，字段位置明确
- ✅ 前端代码简单，无需判断
- ✅ 易于维护和扩展

---

### 2. 前端防御性编程

**始终考虑多种可能的数据结构**：
```javascript
// ✅ 好的做法：使用 || 兜底
const value = data.field1 || data.field2 || defaultValue

// ✅ 好的做法：使用可选链
const value = data?.nested?.field ?? defaultValue

// ❌ 不好的做法：假设固定结构
const value = data.nested.field  // 可能报错
```

### 问题本质
后端API响应结构不统一，导致前端获取字段位置不确定。

### 解决方案
使用逻辑或（`||`）兜底，兼容多种响应结构。

### 关键代码
```javascript
form.basic.competitionId = data.competitionId || registration.competitionId
```
